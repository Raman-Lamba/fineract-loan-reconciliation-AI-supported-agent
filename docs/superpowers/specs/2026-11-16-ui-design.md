# Review page and setup guide

Goal (spec.md): an agent matches messy bank lines to loans in Fineract, posts only clear ones, splits each
80:20 in an auditable ledger, and queues anything unclear for a person with candidates and reasons. Never
guess, never post twice. This adds two things: a page for the person who works the queue, and clear
directions for connecting the agent to a lender's own Fineract and Mifos.

## Decision: a second way to fill in queue.csv, not a second workflow

`python -m ui.serve [--port 8000] [--demo]`, or `.\start.ps1 -Ui`. One module (`ui/serve.py`, `http.server`
from the standard library) and one HTML file (`ui/index.html`, plain JavaScript). No framework, CDN, build
step or new dependency.

A click on Approve or Reject:

1. writes `decision`, `loan_ref`, `approver`, `note` into that line's row of `data/queue.csv`, with
   `review.build.write_queue`, as a person would in Excel;
2. calls `review.apply.run(fc, ok, only=txn_id)`, which is `review.apply`'s former `main()` with one new
   argument: apply only this row and leave the others as they are;
3. reads the outcome back: the row has left the queue (posted, recovered, rejected) or is still there with
   `PROBLEM: ...` in its note, which the page shows on the row.

So validation, the externalId duplicate guard, the 80:20 split, the ledger and the audit log have one
implementation. The page validates nothing itself beyond asking for a name and a loan before it sends.
`queue.csv` stays the single source of truth; the page reads it fresh on every load and every click.

## Requests

| Request | What it does |
|---|---|
| `GET /` | The page, with this run's token and the non-secret settings written in |
| `GET /api/state` | `queue.csv` (candidates split into borrower, loan_ref, amount, due, and Fineract ids for the Mifos link) and the ledger totals from `posting.verify.totals` |
| `GET /api/check` | The seven connection checks |
| `GET /api/verify` | `posting.verify`'s loop: loans in arrears and the ledger checked against Fineract (reads every loan) |
| `GET /partner_report.csv` | Runs `review.report`, then sends the file |
| `POST /api/decide` | The click above. The only request that changes anything |

## Safety

- Bound to 127.0.0.1. A request whose Host header is not `127.0.0.1` or `localhost` gets 403 (stops DNS
  rebinding from another site).
- A change is a POST with an `X-Token` header equal to a random token made at start-up and embedded in the
  page. Another site cannot read the page, so it cannot send the token.
- The password is never put in a response. JSON answers are also scrubbed of it, in case an error text from
  Fineract or the HTTP library ever carried it. The request log has paths only.
- Bank narrations and names are set as text in the page, never as HTML.
- One decision at a time (a lock), since each rewrites `queue.csv`.

## Connection checks (read-only)

One login call (`POST authentication`, which creates nothing), then GETs. Each failure carries a fix in
plain English. Statuses seen on the sandbox on 16 Nov 2026: no status, 404 or 405 for a wrong address, 400
for an unknown tenant, 401 for a wrong user or password.

1. Fineract answers at the URL
2. The tenant exists
3. The login works (and says so if the user has `ALL_FUNCTIONS`, an admin account)
4. INR is an enabled currency
5. Payment types UPI, NEFT, IMPS, NACH exist
6. Loans exist, and how many have an externalId
7. A loan's schedule can be read

If 1, 2 or 3 fails the rest are reported as "not run".

## Changes to existing code

- `review/apply.py`: `main()` became `run(fc, ok, only=None)` plus a three-line `main()`.
- `posting/verify.py`: `read_fineract()` and `totals()` taken out of `main()` so the page shows the same numbers.
- `posting/run.py`: the connector is imported inside `main()`, so the file helpers load without `vendor/`.
  `appender` writes characters the machine's encoding lacks as `\uXXXX` instead of failing after a post, and
  can be closed.
- `statement/fetch_schedules.py`: `fetch(fc, ok)` and `list_loans(fc, ok)`; a loan with no externalId is kept,
  with its account number as `loan_ref` (before, it was skipped, which would have hidden a real lender's loans).

## Demo mode

`--demo` points the data files at a new temporary folder holding three loans and three bank lines, builds
the queue with the real matcher and `review.build`, and answers Fineract calls from memory
(`DemoFineract`). The page shows a DEMO badge. It lets anyone try approve, reject and a refused row without
Docker and without posting anywhere; the unit tests use the same fake.

## Known limits (each marked `# shortcut:` or stated in the README)

- One local user, no login. The approver is a typed name. Several reviewers or remote use need accounts.
- The page applies one row per click. Rows decided in Excel still need `python -m review.apply`.
- A loan known by its account number (`000000042`) loses its zeros in Excel; decide those on the page.
- The permission list for a dedicated Fineract user is verified as names only, not by a run as such a user.
- The Mifos link pattern is read from the web app's route table (1.14), not clicked through.
- `.env` is read at start-up: restart the page after changing it.
